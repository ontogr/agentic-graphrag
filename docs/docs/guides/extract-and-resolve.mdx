# Extract and resolve entities

This guide shows how to extract entities and relations from chunks, and how to resolve duplicate mentions into groups.

## Before you start

The extraction examples use a chunk of text. The resolution examples use a graph. This guide assumes that you finished the [Quickstart](../get-started/quickstart.mdx). Each code block is complete and opens its own connections. The LLM examples read `LLM_BASE_URL`, `LLM_MODEL_ID`, and optionally `LLM_API_KEY` from the environment or from `.env`.

## Extract with the default schema

`BAMLExtractor` sends the chunk to an LLM and returns typed entities and relations. It needs the `llm` extra:

```bash
uv pip install "agentic-graphrag[llm]"
```

{/* pmd-metadata: fixture:llm_env */}

```python
import asyncio

from uuid import uuid4

from agrag.common.data_models.chunk import Chunk
from agrag.common.data_models.graph_schema import GENERIC
from agrag.common.data_models.provenance import TextProvenance
from agrag.ingestion.extract import BAMLExtractor, ExtractionLLMSettings


async def main() -> None:
    text = "Ada Lovelace wrote the first algorithm for the Analytical Engine."
    chunk = Chunk(
        id=uuid4(),
        document_id=uuid4(),
        text=text,
        provenance=TextProvenance(char_start=0, char_end=len(text)),
    )

    # Point at your OpenAI-compatible endpoint with environment variables:
    #   LLM_BASE_URL, LLM_MODEL_ID, and optionally LLM_API_KEY
    settings = ExtractionLLMSettings.from_openai_compatible_env()
    extractor = BAMLExtractor(settings=settings)
    result = await extractor.extract(chunk, GENERIC)
    print(result.entities)


asyncio.run(main())
```

To record what the extractor does, pass a `tracer` to it. See [Trace an agent run](./trace-an-agent-run.mdx).

## Give the model the section heading

When a chunk has a heading path, `BAMLExtractor` sends it as a separate `section` line above the text block, for example `Guide > Setup`. The prompt says that the line is context only. Character offsets still index the chunk text, because the heading is not part of it. Set `include_heading_path=False` to turn this off:

{/* pmd-metadata: fixture:llm_env */}

```python
import asyncio

from agrag.ingestion.extract import BAMLExtractor, ExtractionLLMSettings


async def main() -> None:
    settings = ExtractionLLMSettings.from_openai_compatible_env()
    extractor = BAMLExtractor(settings=settings, include_heading_path=False)


asyncio.run(main())
```

Only `BAMLExtractor` uses the heading path. The local and escalating extractors read the chunk text only. See [Configure chunking](./configure-chunking.mdx) for the embedding side of this configuration.

## Configure extraction

`GlinerExtractor` reads its settings from `ExtractionSettings`. By default, it loads the base GLiNER 2.5 model in full precision and keeps entity spans with a score of at least 0.5. Set environment variables, add them to `.env`, or pass an `ExtractionSettings` object to the extractor. `Graph` accepts a local `Extractor` through `extractor=` and an LLM `LLMExtractor` through `llm_extractor=`.

| Variable | Default | Effect |
| --- | --- | --- |
| `EXTRACTION_MODEL_NAME` | `fastino/gliner2.5-base-v1` | GLiNER checkpoint to load. `fastino/gliner2.5-small-v1` uses less memory and has lower accuracy. |
| `EXTRACTION_DTYPE` | `fp32` | Model precision: `fp32`, `fp16`, or `bf16`. |
| `EXTRACTION_ENTITY_THRESHOLD` | `0.5` | Lowest entity score kept, unless a label has its own threshold. |
| `EXTRACTION_LABEL_THRESHOLDS` | `{}` | JSON object of per-label thresholds. |

The base model needs about 850 MB for the first model download. `fp16` and `bf16` reduce model memory use, but their speed and support vary by device and PyTorch build. The model loads in `fp32` before it is cast. Check extraction results on your data before using a lower precision in production.

For example, set per-label scores and the precision in `.env`:

```dotenv
EXTRACTION_DTYPE=bf16
EXTRACTION_LABEL_THRESHOLDS={"Person": 0.7, "Organization": 0.6}
```

You can set the same values in Python:

```python
from agrag.ingestion import ExtractionSettings, GlinerExtractor

settings = ExtractionSettings(dtype="bf16", label_thresholds={"Person": 0.7})
extractor = GlinerExtractor(settings=settings)
```

`Graph` takes the settings from an injected, top-level `GlinerExtractor`. For a custom extractor, pass `extraction_settings=` to `Graph.open`. If you pass settings to both the graph and a top-level GLiNER extractor, their values must match. Graph does not inherit or compare GLiNER settings inside an `EscalatingExtractor`, including nested wrappers. When composing extractors, pass the same settings to Graph and the wrapped GLiNER extractor yourself.

See the [configuration reference](../reference/configuration.mdx#local-extraction) for all extraction settings. Each extracted entity and relation has a `confidence` score from the model.

`EXTRACTION_MODE` accepts `gliner`, `hybrid` (the default), and `llm`. `Graph.effective_mode` reports the mode selected for the graph, not the class of the extractor. When `hybrid` has no LLM configured, the mode becomes `gliner` and Graph logs a warning. An injected custom local extractor still runs unchanged in that mode; Graph does not replace it with GLiNER. `Graph` can configure both extractor slots in `hybrid`, but it does not yet escalate automatically between them. To escalate now, compose `GlinerExtractor` and an LLM extractor with `EscalatingExtractor`, as shown below.

For LLM-only ingestion, pass `extraction_settings=ExtractionSettings(mode="llm")` and `llm_extractor=BAMLExtractor(...)` to `Graph.open`. Do not pass `extractor=` in that mode. If you omit `llm_extractor=`, `Graph` reads `EXTRACTION_LLM_CLIENTS`, or `LLM_BASE_URL` with `LLM_MODEL_ID`, to build it. `Graph.llm_model_name` reports the configured client models, or the class name of a custom LLM extractor.

## Run locally first, escalating to an LLM

`GlinerExtractor` runs a local model. `EscalatingExtractor` runs it first and calls the LLM only when the local result is weak. It needs both extras:

The extractor treats a chunk as weak when it finds no entities in at least `min_chunk_words` words (8 by default), or when the mean `confidence` of its entities is below `min_confidence` (0.5 by default). GLiNER keeps entities at or above 0.5 by default, so the mean-confidence condition needs a higher `min_confidence` or a lower entity threshold to fire. For example, set `min_confidence=0.75` on `EscalatingExtractor` to escalate retained entities with a mean score below 0.75.

When you pass an `EscalatingExtractor` with an LLM fallback to `Graph`, use `hybrid` mode. The graph recognizes the wrapped LLM and reports `hybrid` without requiring an environment-configured client. `gliner` mode rejects a wrapper that could invoke an LLM, including nested wrappers.

```bash
uv pip install "agentic-graphrag[extract,llm]"
```

{/* pmd-metadata: fixture:llm_env */}

```python
import asyncio

from uuid import uuid4

from agrag.common.data_models.chunk import Chunk
from agrag.common.data_models.graph_schema import GENERIC
from agrag.common.data_models.provenance import TextProvenance
from agrag.ingestion.extract import (
    BAMLExtractor,
    EscalatingExtractor,
    ExtractionLLMSettings,
    GlinerExtractor,
)


async def main() -> None:
    text = "Ada Lovelace wrote the first algorithm for the Analytical Engine."
    chunk = Chunk(
        id=uuid4(),
        document_id=uuid4(),
        text=text,
        provenance=TextProvenance(char_start=0, char_end=len(text)),
    )

    settings = ExtractionLLMSettings.from_openai_compatible_env()
    extractor = EscalatingExtractor(
        primary=GlinerExtractor(),
        escalate_to=BAMLExtractor(settings=settings),
    )
    result = await extractor.extract(chunk, GENERIC)
    print(result.entities)


asyncio.run(main())
```

## Configure the LLM provider

Set `EXTRACTION_LLM_CLIENTS` (or a `.env` file) to point at any supported provider: Anthropic, OpenAI, Azure OpenAI, AWS Bedrock, Google AI, Vertex AI, or a self-hosted OpenAI-compatible endpoint through `openai-generic`. The value is a JSON list of client configs:

```text
EXTRACTION_LLM_CLIENTS=[{"name": "c", "provider": "openai-generic", "model": "your-model-name", "base_url": "https://your-endpoint.example.com/v1", "api_key": "your-api-key"}]
EXTRACTION_LLM_STRATEGY=single
```

A strategy of `fallback` or `round_robin` composes more than one client.

Alternatively, use `ExtractionLLMSettings.from_openai_compatible_env()` to read `LLM_BASE_URL`, `LLM_MODEL_ID`, and `LLM_API_KEY`. `LLM_API_KEY` is optional. The call raises `RuntimeError` when `LLM_BASE_URL` or `LLM_MODEL_ID` is missing.

## Resolution runs inside every write

You never call resolution directly. `graph.add()` resolves every batch automatically. Exact-name identity groups mentions without evidence. A fuzzy fast path merges near-identical names. Embedding similarity decides the rest. A capped LLM tier reviews only the ambiguous band. Raw entity nodes are permanent. Confirmed non-exact matches persist as `MATCHES` edges with a derived resolved node. No call deletes a node.

```python
import asyncio

from agrag.common.data_models.graph_schema import GENERIC
from agrag.embedding import build_embedder
from agrag.graphdb import build_graph_store
from agrag.ingestion import Graph
from agrag.ingestion.extract import GlinerExtractor


async def main() -> None:
    graph_store = build_graph_store("neo4j")
    graph = await Graph.open(
        schema=GENERIC,
        graph_store=graph_store,
        embedder=build_embedder("ibm-granite/granite-embedding-small-english-r2"),
        extractor=GlinerExtractor(),
    )
    try:
        result = await graph.add(text="Ada Lovelace wrote the first algorithm.")
        print(result.resolution.exact_match_hits)
        print(result.resolution.ambiguous_count)
    finally:
        await graph_store.close()


asyncio.run(main())
```

`Graph.open` has no resolution configuration. Resolution uses the schema, the embedder, and the extractor that you pass to it. Inspect every run through the resolution stats on the returned `AddResult`.

## Consolidate the whole graph

`consolidate()` runs the same resolution as a full pass over every persisted entity of each type. Run a dry run first, then apply:

```python
import asyncio

from agrag.common.data_models.graph_schema import GENERIC
from agrag.embedding import build_embedder
from agrag.graphdb import build_graph_store
from agrag.ingestion import Graph
from agrag.ingestion.extract import GlinerExtractor


async def main() -> None:
    graph_store = build_graph_store("neo4j")
    graph = await Graph.open(
        schema=GENERIC,
        graph_store=graph_store,
        embedder=build_embedder("ibm-granite/granite-embedding-small-english-r2"),
        extractor=GlinerExtractor(),
    )
    try:
        await graph.add(text="Ada Lovelace wrote the first algorithm.")

        report = await graph.consolidate()
        print([(m.entity_a_id, m.entity_b_id) for m in report.would_match])
        print(report.ambiguous_count)

        applied = await graph.consolidate(apply=True)
    finally:
        await graph_store.close()


asyncio.run(main())
```

A dry run writes nothing. An apply run writes `MATCHES` edges and derived resolved nodes. It reports exactly the matches it wrote. LLM review calls stay bounded no matter how large the graph grows.

## Re-evaluate specific entities

`reevaluate()` re-runs the same resolution for entities you name, when new evidence lands or a past decision looks wrong. It adds newly confirmed matches. It deactivates edges that the current evidence no longer supports. It leaves every entity outside the list untouched:

```python
import asyncio

from uuid import UUID
from agrag.common.data_models.graph_schema import GENERIC
from agrag.embedding import build_embedder
from agrag.graphdb import build_graph_store
from agrag.ingestion import Graph
from agrag.ingestion.extract import GlinerExtractor


async def main() -> None:
    graph_store = build_graph_store("neo4j")
    graph = await Graph.open(
        schema=GENERIC,
        graph_store=graph_store,
        embedder=build_embedder("ibm-granite/granite-embedding-small-english-r2"),
        extractor=GlinerExtractor(),
    )
    try:
        await graph.add(text="Ada Lovelace worked with Charles Babbage.")
        rows = await graph_store.execute_read(
            "MATCH (e:_Node:Person) RETURN e.id AS id LIMIT 2"
        )
        entity_ids = [UUID(str(row["id"])) for row in rows]

        report = await graph.reevaluate(entity_ids)
        print(report.matches_added)
        print(report.matches_removed)
    finally:
        await graph_store.close()


asyncio.run(main())
```

There is no automatic trigger. A caller that learns something new calls `reevaluate()` explicitly.

`Resolver.resolve()` also takes an optional `neighbors_by_index` map of per-entity neighboring-relationship strings, which batched `LLMVerify` calls send to the model as extra context. `Graph.add()` and `Graph.consolidate()` build one automatically from a batch's extracted relations and each persisted entity's stored graph edges.
