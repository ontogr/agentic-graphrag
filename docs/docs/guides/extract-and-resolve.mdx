# Extract and resolve entities

This guide shows how to extract entities and relations from chunks, and how to
resolve duplicate mentions into groups.

## Extract with the default schema

```python
import asyncio
from agrag.common.data_models.graph_schema import GENERIC
from agrag.ingestion.extract import BAMLExtractor, ExtractionLLMSettings


async def main():
    # Point at your OpenAI-compatible endpoint via environment variables:
    #   LLM_BASE_URL, LLM_MODEL_ID, and optionally LLM_API_KEY
    settings = ExtractionLLMSettings.from_openai_compatible_env()
    extractor = BAMLExtractor(settings=settings)
    result = await extractor.extract(chunk, GENERIC)
    print(result.entities)


asyncio.run(main())
```

`BAMLExtractor` needs the `llm` extra:

```bash
pip install "agentic-graphrag[llm]"
```

## Run locally first, escalating to an LLM

```python
import asyncio
from agrag.common.data_models.graph_schema import GENERIC
from agrag.ingestion.extract import (
    BAMLExtractor,
    EscalatingExtractor,
    ExtractionLLMSettings,
    GlinerExtractor,
)


async def main():
    settings = ExtractionLLMSettings.from_openai_compatible_env()
    extractor = EscalatingExtractor(
        primary=GlinerExtractor(),
        escalate_to=BAMLExtractor(settings=settings),
    )
    result = await extractor.extract(chunk, GENERIC)
    print(result.entities)


asyncio.run(main())
```

`GlinerExtractor` needs the `extract` extra:

```bash
pip install "agentic-graphrag[extract]"
```

## Configure the LLM provider

Set `EXTRACTION_LLM_CLIENTS` (or a `.env` file) to point at any supported
provider — Anthropic, OpenAI, Azure OpenAI, AWS Bedrock, Google AI, Vertex AI,
or a self-hosted OpenAI-compatible endpoint via `openai-generic`.

Alternatively, use `ExtractionLLMSettings.from_openai_compatible_env()` to
read from `LLM_BASE_URL`, `LLM_API_KEY`, and `LLM_MODEL_ID` environment
variables.

## Resolution runs inside every write

You never call resolution directly. `graph.add()` resolves every batch
automatically: exact-name identity groups mentions without evidence, a
fuzzy fast path merges near-identical names, embedding similarity decides
the rest, and a capped LLM tier reviews only the ambiguous band. Raw
entity nodes are permanent. Confirmed non-exact matches persist as
`MATCHES` edges with a derived resolved node, never by deleting a node.

```python
result = await graph.add(text="Ada Lovelace wrote the first algorithm.")
print(result.resolution.exact_match_hits)
print(result.resolution.ambiguous_count)
```

Configure resolution through the settings you pass when you open the
graph: the schema, the embedder, and the extractor. Inspect every run
through the resolution stats on the returned `AddResult`.

## Consolidate the whole graph

`consolidate()` runs the same resolution as a full pass over every
persisted entity of each type. Dry-run first, then apply:

```python
report = await graph.consolidate()
print([(m.entity_a_id, m.entity_b_id) for m in report.would_match])
print(report.ambiguous_count)

applied = await graph.consolidate(apply=True)
```

A dry run writes nothing. Applying writes `MATCHES` edges and derived
resolved nodes, and reports exactly the matches it wrote. LLM review
calls stay bounded no matter how large the graph grows.

## Re-evaluate specific entities

`reevaluate()` re-runs the same resolution for entities you name, when
new evidence lands or a past decision looks wrong. It adds newly
confirmed matches, deactivates edges the current evidence no longer
supports, and leaves every entity outside the list untouched:

```python
report = await graph.reevaluate([entity_id_a, entity_id_b])
print(report.matches_added)
print(report.matches_removed)
```

There is no automatic trigger: a caller that learns something new calls
`reevaluate()` explicitly.

## Define your own schema

```python
from agrag.common.data_models.graph_schema import (
    EntityType,
    GraphSchema,
    RelationType,
)

schema = GraphSchema(
    name="clinical",
    version="1",
    entities=[EntityType(label="Drug", description="A medication.")],
    relations=[],
)
```
