# Introduction

Agentic GraphRAG is an open source Python framework that connects enterprise knowledge, conversation history, and decision traces in one graph. Agents can find evidence, resume work across sessions, and review decisions when their sources change.

## What it keeps in the graph

The graph has three connected layers. Enterprise knowledge holds documents with their sections, chunks, entities, relations, and community summaries. Conversation history holds named tasks, ordered events, and steps. Events include agent messages, tool calls, and tool results, so conversation history is more than a chat transcript. Decision traces hold conclusions, concise rationales, assumptions, and explicit supports to passages, task events, or other decisions. They are stored records, not hidden model reasoning.

Add documents to build a knowledge graph shaped by your schema. Agents search the graph, read the exact passage behind each result, and cite it. They record decisions with supports that identify the evidence they rely on. A later session resumes a task from its recorded events and steps, and source changes flag affected decisions for review.

The company-briefing workflow uses annual-report passages to support decisions about a business risk. A later run can resume its task and inspect the saved decision. A correction to the working copy flags decisions that cite the changed text for review.

## Three ways to use it

Use the Python library when you want direct control. `Graph` adds documents, the functions in `agrag.evidence` search and cite, `agrag.history` records task events and steps, and `agrag.decisions` records supported decisions. Use `build_agent` for a task-scoped agent that searches your documents, records its work, and answers with numbered sources. Run `agrag-mcp` to give an MCP client tools for search, citation, conversation history, and decision traces.

## How it works

<Diagram folder="docs" name="introduction" alt="Ingestion stores enterprise knowledge in one graph. An agent or MCP client searches the graph, records conversation history, and saves decision traces with evidence supports. The agent returns a cited answer." />

*Ingestion builds the graph. Agents and MCP clients read evidence, record task activity, and save supported decisions.*

1. You add documents. Agentic GraphRAG loads them, splits them into chunks, and extracts entities and relations.
2. Agentic GraphRAG resolves duplicate mentions and writes the graph and its indexes to the graph database.
3. You ask a question. The agent discovers and fetches evidence from the graph.
4. The agent checks its citations against the fetched evidence and writes an answer with numbered sources.
5. The agent records messages, tool calls, and tool results as task events. It records progress as steps and saves decisions with explicit supports.

## Who it is for

Use Agentic GraphRAG if you build agents that answer from documents that you own, need answers that cite their sources, and want agents that continue a task across sessions. You can define your own entity and relation types.

## What you need

- Python 3.11 or newer.
- A [Neo4j or FalkorDB database](../concepts/graph-storage.mdx). Both store the graph and its search indexes.
- An OpenAI-compatible LLM endpoint for the built-in agent. Embeddings and local extraction run on your machine.
